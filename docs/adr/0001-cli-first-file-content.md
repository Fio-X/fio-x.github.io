# ADR-0001：CLI-first 文件型内容源

- 状态：Accepted
- 日期：2026-07-29

## 背景

Fio Blog 是个人作品与写作站，目标平台是 GitHub Pages。它需要让作者能够持续写文章、管理作品图片，同时保留 Git 的版本审阅能力。引入数据库或后台 CMS 会增加运行时服务、认证、备份和部署成本，而当前站点不需要在线多人编辑或动态内容接口。

## 决策

使用 Git 管理的 Markdown 文件和本地媒体作为唯一内容源：

- 文章位于 `content/articles/`。
- 作品位于 `content/works/`。
- 固定页面位于 `content/pages/`。
- 公开媒体位于 `public/media/`。
- `scripts/blog.ts` 提供创建内容、加入媒体、校验和构建命令。
- `lib/content.ts` 是构建期内容规则的最终来源，负责解析、校验、草稿过滤、排序和分类/标签派生。

CLI 是作者便利入口，不是另一套内容规则；通过其他方式手动创建的合法 Markdown 也必须通过同一内容层校验。

## 理由

- Git diff 可以审阅正文、元数据和图片路径变化。
- 静态导出可以在没有数据库和运行时服务器的情况下发布。
- Markdown 适合长期保存、迁移和批量编辑。
- 内容校验集中在一个模块，避免各页面重复实现规则。

## 后果

### 正面

- 无 CMS、数据库和在线后台的运营成本。
- 内容变更可回滚、可追踪、可在本地预览。
- 草稿、媒体和元数据可以在构建期统一检查。

### 代价

- 作者需要使用本地命令、编辑器和 Git。
- 内容不能在网站后台直接编辑。
- 每次公开内容变化都需要重新构建和发布。
- 图片和第三方内容的授权审阅仍由作者负责，工具不能替代法律判断。

## 备选方案

- 使用数据库和后台 CMS：适合多人在线编辑，但超出当前规模并增加运行时依赖。
- 使用第三方 Headless CMS：减少本地编辑工作，但引入外部服务、账号和构建时网络依赖。
- 使用 MDX：表达能力更强，但允许内容直接执行组件逻辑，增加内容审阅和维护复杂度。
